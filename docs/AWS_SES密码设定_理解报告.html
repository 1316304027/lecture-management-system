一、你要的逻辑（完整版，不是缩短版）

角色能做什么不能做什么
管理者创建账号、编辑姓名邮箱角色、PWリセット（触发邮件）❌ 不能输入/看到用户密码
讲师/学生收 AWS SES 邮件 → 点链接 → 自己设密码 → 登录❌ 未设密码不能登录
管理者账号系统初始化固定密码（admin@test.com）不走 SES
和领导说的核心：密码只有用户本人知道。管理员只能「重置」= 发邮件让用户重新设，就像账号解锁后强制改密。
日语 · 30秒（必背）
管理者は講師・受講者のパスワードを設定・変更できません。アカウント作成時とリセット時に、AWS SES でパスワード設定用リンクをメール送信します。ユーザー本人のみがリンクからパスワードを設定し、その後ログインできます。これは情報セキュリティと AWS 活用の両方を満たす設計です。

二、完整技术链路（发表 Demo 指着讲）

【创建用户】
管理员 POST /admin/accounts/create（只有姓名+邮箱+角色）
  → UserService.createUser()
  → DB: password_not_set=true, 密码=随机不可猜哈希
  → PasswordResetService.createToken() → password_reset_tokens 表
  → EmailService.sendPasswordSetupEmail()  ★ AWS SES SDK
  → 用户邮箱收到链接: {APP_BASE_URL}/setup-password?token=uuid

【用户设密码】
用户点邮件链接 GET /setup-password?token=xxx
  → PasswordSetupController 验证 token（24小时有效）
  → 用户输入新密码 POST /setup-password
  → UserService.setupPasswordViaToken() → BCrypt 存库
  → password_not_set=false → 可登录

【管理员 PWリセット】
POST /admin/accounts/{id}/reset-password
  → 旧密码作废 + 新 token + SES 再发邮件
  → 用户必须重新点链接设密码（和锁死后重设一样）

【登录拦截】
POST /login
  → 若 password_not_set=true → 拒绝，提示去收邮件
AWS 用了什么： SES（Simple Email Service）发信 · EC2 IAM 角色认证（无密钥硬编码）· 与已有 S3 同属 AWS SDK v2

四、AWS 部署必做（否则邮件发不出）

  1. SES 验证发件邮箱：控制台 Verified identities → 验证 SES_FROM_EMAIL
  2. IAM 权限：EC2 角色加 ses:SendEmail
  3. 环境变量： 
    APP_BASE_URL=http://你的EC2公网IP
SES_FROM_EMAIL=验证过的邮箱
MAIL_ENABLED=true
  4. SES 沙盒：测试时收件人邮箱也要在 SES 验证，或申请 Production access
日语 · AWS 说明
パスワード設定メールは AWS SES で送信しています。EC2 の IAM ロールで認証し、ハードコードされたキーは使いません。S3 と同様に AWS SDK v2 を使用しています。

八、Q&A 日语参考答案

为什么管理员不能设密码？

管理者がパスワードを知ると漏洩リスクがあります。業界標準では本人のみがパスワードを管理します。

邮件发不出去怎么办？

SES の送信元検証、IAM 権限、サンドボックスの受信者検証を確認します。本番では Production access を申請します。

这是大改动吗？

中等规模：新增 token 表、SES Service、setup-password 页面。核心登录仍是 Session + BCrypt。
